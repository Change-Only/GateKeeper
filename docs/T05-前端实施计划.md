### 4 个「新建（APIM 专属）」页判定依据

团队简报要求 4 个新建页。本计划按「**无旧前端对应页 + 纯新增 APIM 平台能力**」判定，定为：

1. **`sys-env` 环境与网关** —— 环境主数据 + 网关路由/版本预览（灰度路由可视化构件宿主），零旧前端对应。
2. **`sys-bizline` 业务线管理** —— `biz_line` 新域，零旧前端对应。
3. **`sys-notify` 通知渠道** —— `notify_channel` 新域，零旧前端对应。
4. **`perm-datascope` 数据权限** —— `sys_role_data_scope` 数据治理 scope，零旧前端对应。

> ⚠️ 注意：上表 `sys-dict`/`sys-config` 虽也被标为「改造」，但其**后端 Controller 当前不存在**（见 §8 风险）；`perm-datascope` 亦无专属 Controller。这 3 页的实现须后端补课或前端先按约定契约打桩（mock 先行）。其余 17 页后端接口齐备，可直接联通。

`encryption`（加解密）、`screen`（数据大屏）、`access-doc`（接入文档）保留路由，但**不加入新侧边菜单**（加解密能力并入 `sys-security` 安全策略；大屏/接入文档保留独立公开入口）。旧 `security/ban|event|rule` 三条路由合并进 `mon-block` / `sys-security`。

## 2. 后端接口契约总览（实现者必读）

所有路径**已带 `/api` 前缀**（context-path）。统一响应包装：`Result<T> = { code:200, data, message }`，axios 拦截器已对 `code!==200` 弹错、对 401 清登录跳 `/login`。

### 2.1 统一分页响应

列表类接口（App/Env/BizLine/User/Role/Interface/Grant 等）返回 `Result<PageResult<T>>`，前端取 `res.data`：
```
PageResult<T> = { records: T[], total: number, current: number, size: number, pages: number }
```
**子列表类接口**（按 `apiId` 查参数/版本/环境配置、告警规则、通知渠道、凭证、调用日志等）返回 `Result<List<T>>`（非分页，前端直接取数组）。

### 2.2 登录契约（菜单权限来源）

`POST /api/auth/login` → body `{username, password}` → 返回：
```
{ code:200, data: {
    token: "eyJ...",
    user: { id, username, realName },
    perms: ["app:list","grant:create", ...],   // 权限点编码数组
    permCount: 27
} }
```
**`perms` 数组是菜单/按钮权限闸门的唯一数据源**（JWT 不塞权限，服务端 `PermissionInterceptor` 实校验）。

## 3. 逐页规格

> 字段名取自原型 `MOCK.*`（原型 736–1135 行）；枚举语义严格参照 `docs/原型枚举字典.md`（**不同实体 status 含义不同，禁止套用**）。`columns` 为列表表头，`form` 为弹窗表单字段，`dialog` 为对话框。

### 3.1 dashboard 概览（改造）
- **route**：`/dashboard`（已有）
- **端点**：`/dashboard/screen/overview` 等 5 个
- **内容**：顶部 5 个 KPI 卡（接口总数/应用总数/近24h调用量/成功率/平均延迟，含趋势）；待办清单（待审核接口/待审批授权/待审核应用/密钥即将过期/未处理告警，每项可跳对应页）；风险看板（高危/中/低，可跳 `mon-calllog`/`perm-matrix`/`app-list`）；Top5 接口榜、Top5 应用榜（成功率/延迟）。
- **复用**：现有 `dashboard/Index.vue` + echarts；新增「待办/风险」卡片（数据来自各域统计，原型用静态 MOCK，需确认后端是否提供聚合接口，否则前端按各 list 计数）。

### 3.2 app-list 应用列表（改造，最大页）
- **route**：`/app`（已有 → 改为 `/app` 下 `app-list`）
- **端点**：见 §2.3；列表 `GET /api/app/list` 返回 `PageResult<App>`
- **columns**：应用名称、业务线、类型、状态、密钥数、授权接口数、近24h调用、负责人、操作
- **主操作**：新建应用（dialog：应用名称/编码、业务线`lineId`、类型`appType`、负责人、联系人、环境范围`envScope[]`、描述）、启停、删除
- **内嵌 4 个 Tab（点击行展开/详情抽屉）**：
  1. **密钥凭证**（api-credential）：columns 别名/AppKey(脱敏)/环境/状态/过期时间/最后使用；操作 创建(`/app-credential/create`，**仅此一次返回明文 secret，弹窗展示`secretMask`+明文`appSecret`**)、灰度轮换(`/app-credential/rotate`)、完成轮换、吊销、改别名/过期(`/app-credential/{id}/update`)
  2. **授权接口**（grants）：columns 接口/分组/环境/QPS/日配额/有效期/状态/理由；跳转 perm-matrix
  3. **配额**（appQuotas）：全局QPS/日配额/月配额/并发（form：`/app/{id}/rate-limit`）
  4. **IP 白名单**：IP/CIDR/环境/备注（form：`/app/{id}/ip-whitelist`）
- **校验**：appName/appCode 必填；appCode 唯一；envScope 至少 1 项；外部应用(`appType=2`)强制要求 IP 白名单（呼应 config `external.ip.whitelist.required`）。

  4. **变更历史**（api-change-log）：时间/操作人/类型`changeType`/字段/变更前→后/原因。只读。

- **操作（审批流状态机：0待审批→1已生效→2过期/3撤销/4驳回）**：

  - 高危操作（approve/revoke）需二次确认
- **矩阵视图**：行=接口、列=应用×环境，单元格=授权状态色块（复用 StatusTag 构件）。

## 8. 风险与待决项（须跨团队对齐）

1. 🔴 **`sys-config` 与 `sys-dict` 后端 Controller 缺失**：当前 25 个 Controller 中**无 `ConfigController` / `DictController`**（`sys_config` / `sys_dict` 表在 schema 但无对外接口）。这两页无法真实联通。**行动**：请 team-lead 派后端补 `ConfigController`(按 `configGroup` 读写) 与 `DictController`(dict+item CRUD)；T05 前端先按 §3.13/§3.16 约定 DTO 用原型 `MOCK.configs`/`MOCK.dicts` 打桩，后端到位后切换。
2. 🟠 **`perm-datascope` 无专属 Controller**：`sys_role_data_scope` 表存在但无管理接口。**行动**：后端补 `GET/PUT /api/sys/role-data-scope/{roleId}`；前端先打桩。
3. 🟠 **`sys-security` 安全策略表单后端归属不明**：现有 `SecurityController` 管 rule/event/ip-ban；「安全策略」键值（configGroup=SECURITY/GATEWAY）预期走 config 接口（同风险 1）。统一归口到 `ConfigController` 后实现。
4. 🟡 **登录 `perms` 与前端菜单 perm 码不完全一致**：原型 `MOCK.menus` 仅含 28 个权限点子集，本计划 §7 标 ⚠️ 的 9 个 view 权限码为推断。需后端提供 `sys_menu` 种子中的真实 `permCode` 列表对齐（或前端登录后拉 `/api/sys/menu/perm-points` 校验）。
5. 🟡 **dashboard 聚合接口**：原型用静态 `MOCK.dashboard`；后端 `DashboardController` 仅 `screen/*` 5 个，是否提供待办/风险聚合需确认（否则前端对各 list 计数拼装）。
6. 🟡 **环境不可伪造**：前端不传 `env_code`，环境由 `GK_ENV` + 凭证 `env_code` 决定（总纲铁律 6）；前端环境筛选下拉仅用于「查看维度」，不下发到网关请求。
