# GateKeeper 项目梳理（产品视角）

> 更新日期：2026-08-30 · 梳理人：产品通

---

## 一、一句话定位

**GateKeeper 是面向企业的 API 集中管控与安全网关平台**：把分散在各后端系统的接口统一收口，对外提供"谁可以调、从哪调、多久调一次、传输是否加密、异常能否发现"的标准化管控，并对每次调用完整审计与可视化。

核心价值八字诀：**统一入口 · 权限可控 · 加密传输 · 流量可限 · 异常可防 · 调用可审 · 安全可溯 · 态势可视**。

## 二、为什么存在（要解决的问题）

| 痛点 | GateKeeper 的解法 |
|---|---|
| 接口散落在各系统，无统一出口 | 网关统一收口 `/gateway/**`，一套链路管理所有后端 |
| 鉴权各自为政，密钥裸奔 | AppKey/AppSecret + 签名/时间戳/Nonce 防重放统一校验 |
| 谁有权限调哪个接口说不清 | 应用-接口授权矩阵 + 分组授权 + 批量授权 |
| 接口被刷/被攻击无感知 | 令牌桶限流 + 并发/日调用上限 + 异常调用检测（5 类）+ IP 封禁 |
| 敏感数据明文传输 | SM2/SM3/SM4 国密 + AES 国际算法，应用/接口级独立配置 |
| 出问题无法追溯 | 全链路调用日志（入参/响应/耗时/状态/IP）+ 操作审计 |
| 故障无人知晓 | 告警中心（等级/未读/处置闭环）+ 数据大屏实时态势 |

## 三、目标用户与角色

| 角色 | 诉求 | 用到的模块 |
|---|---|---|
| 平台管理员（运维/安全） | 管控应用与接口、看态势、接告警 | 应用/接口/权限/加密/安全/告警/大屏 |
| 后端开发者（接入方） | 快速接入、密钥管理、查调用 | 接入文档、应用管理、调用日志、加解密 |
| 业务应用方（调用方） | 凭 AppKey 稳定调用 | 网关入口（无需进入管理后台） |
| 决策者 | 全局态势、审计合规 | 数据大屏、操作审计、统计仪表盘 |

## 四、功能地图

### 管理端（8 大模块）
应用管理（注册/密钥/启停/到期/IP 白名单/频率限制）· 接口管理（注册/分组/超时/接口级加密）· 权限管理（授权矩阵/分组/批量）· 加解密管理（国密+国际算法配置）· 安全防护（5 类检测规则 + 手动/自动封禁）· 调用日志（筛选/详情/百万级异步导出）· 告警中心（等级汇聚/未读/处置闭环）· 数据大屏（实时态势/排行/趋势，投屏）

### 网关请求链路（8 环节）
应用校验 → IP 白名单 → 封禁检查 → 频率限制 → 权限校验 → 加解密 → 请求转发 → 日志审计（全程 O(1) Redis 支撑）

## 五、技术架构与亮点

| 层面 | 选型 |
|---|---|
| 前端 | Vue 2.7 + Element UI + ECharts 5（按需引入）+ Knife4j 文档 |
| 后端 | Java 8 + Spring Boot 2.7 + MyBatis-Plus，责任链网关 Handler 链 |
| 加密 | Bouncy Castle（SM2/3/4）+ JCE（AES） |
| 中间件 | MySQL 8（业务/日志/告警）+ Redis 6（限流计数/封禁/实时统计） |
| 部署 | Docker Compose 一键编排（mysql/redis/backend/frontend + 健康检查 + 初始化建表） |

**亮点**：组合索引降写放大；异步背压（有界线程池 + CallerRunsPolicy）；百万级导出异步化（分批流式+临时文件原子改名）；**Redis 故障 fail-open 降级 + 健康监控**，防护组件失效不拖垮业务链路。

## 七、指标体系建议（上线后）

**北极星指标**：网关月度成功调用数（直接度量"业务经网关的流量规模"）

| 类型 | 指标 | 说明 |
|---|---|---|
| 驱动 | 接入应用数 / 接入接口数 / 授权覆盖率 | 平台采用度 |
| 驱动 | 调用成功率、P95 延迟 | 稳定性，延迟目标 <200ms |
| 健康 | 限流命中率、封禁生效数、未读告警数 | 安全防护活跃度（异常检测量/总调用 <5% 为健康） |
| 健康 | 日志落库成功率、导出任务成功率 | 数据链路可靠 |
| 反指标 | 平均事故响应时长（MTTR） | 告警→处置闭环效率 |
