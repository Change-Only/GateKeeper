# GateKeeper 路线图 RICE 优先级评分

> 更新日期：2026-08-30 · 评分人：产品通
> 评分框架：**RICE = (Reach × Impact × Confidence) / Effort**
> 输入来源：`docs/项目梳理-产品视角.md` 第八节路线图候选项 + 遗留任务清单

---

## 一、评分口径

| 维度 | 口径 | 取值 |
|---|---|---|
| **Reach 触达** | 一个季度内该事项影响到的对象规模（调用请求量、用户数、团队成员数、部署环境数），按相对量纲估算 | 1-5（相对分） |
| **Impact 影响** | 对单个触达对象的效用强度：3=决定能否上线，2=显著改善，1=明显，0.5=轻微，0.25=锦上添花 | 0.25 / 0.5 / 1 / 2 / 3 |
| **Confidence 信心** | 对以上估算的把握（有数据/已完成设计=高，有原型/部分验证=中，纯推断=低） | 50% / 70% / 90% / 100% |
| **Effort 工作量** | 全部投入（设计+开发+测试+验证），含返工风险 | 人·周 |

> 说明：Reach 用相对分而非绝对数，是因为候选事项的触达对象不同质（流量 vs 人数 vs 环境），相对分更可比。

## 四、结论要点

1. **前两名是典型的"低成本高杠杆"快赢项**：合计不到 1 人·周，却分别消除最大交付风险（改动未入库）和最大性能隐患（索引未落地）。建议本周内完成，与原 Now 清单一致。
2. **Docker E2E 是唯一 Impact=3 的近期项**：它决定"能不能上线"，RICE 排名低于两项快赢仅因为工作量大——**不应因分数推迟**，它是 Now 批次的主线。
3. **Next 批次内部排序微调**：告警渠道（3.6）> ESLint（3.0）> 监控指标（2.8），三者可部分并行；监控指标建议放在 E2E 联调之后，届时真实环境可顺手验证指标口径。
4. **Later 三项均为"触发条件驱动"而非时间驱动**：等保客户线索→提前 HTTPS 双栈；单节点 QPS/可用性告警→水平扩展；日志表体量破千万→冷热分层。**建议设触发器而不是排期**。
5. **两个"低分但零成本"事项**（git 归档、ESLint）的分数被 Effort 拉高，本质是"顺手就该做"的卫生项，不应占用路线图讨论带宽。
