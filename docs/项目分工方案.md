**创建任务 Prompt：**

```
你是后端开发工程师。请阅读以下文件：
- project.json（项目元信息）
- docs/PRD.md（产品需求）
- docs/database-design.md（数据库设计）
- design/spec.md（设计规范参考）

技术栈：Java 8 + Spring Boot 2.7.x + MyBatis-Plus + Hutool + MySQL 8 + Redis + Bouncy Castle + Maven

请完成后端开发，代码放在 src/backend/ 目录下：

1. 项目初始化：
   - Maven 项目结构，pom.xml 引入 Spring Boot、MyBatis-Plus、MySQL 驱动、Hutool、Redis、Bouncy Castle（国密）、Knife4j
   - application.yml 配置数据库连接、Redis 连接、服务器端口 8080

2. 网关代理核心（最重要）— 责任链模式实现请求处理链路：
   实现 /gateway/** 统一入口，按顺序执行以下 Handler：
   a. IpWhitelistHandler — IP 白名单校验（支持 CIDR 网段匹配，从 app_ip_whitelist 表加载）
   b. IpBanCheckHandler — IP 封禁检查（从 Redis 和 ip_ban 表检查，支持全局封禁和针对应用封禁）
   c. AppAuthHandler — 应用状态校验（验证 AppKey、应用是否启用、是否已过期）
   d. RateLimitHandler — 频率限制（基于 Redis + 令牌桶算法，检查 QPS/并发/日调用量）
   e. PermissionHandler — 权限校验（校验应用是否有该接口调用权限）
   f. EncryptionHandler — 加解密处理（入参解密：根据接口配置的算法解密；响应加密：根据配置加密返参）
   g. ForwardHandler — 请求转发（使用 RestTemplate 转发至后端真实服务）
   h. LogHandler — 日志记录（异步记录完整调用日志到 api_call_log 表）
   每个 Handler 可中断链路并返回明确的错误码和错误信息

3. 加解密模块（crypto 包）：
   - SM2 非对称加密：密钥生成、加密、解密、签名、验签
   - SM3 密码杂凑：摘要计算
   - SM4 对称加密：ECB/CBC/CFB/OFB/CTR 模式
   - AES 对称加密：128/192/256 位密钥，ECB/CBC/GCM 模式
   - MD5/SHA256 摘要算法
   - CryptoService 统一接口：encrypt(algorithm, data, key, config) / decrypt(algorithm, data, key, config)
   - 加解密配置可按应用维度和接口维度独立设置，接口维度优先

4. 限流模块（ratelimit 包）：
   - 基于 Redis + 令牌桶算法
   - 支持 QPS 限制、并发数限制、日调用量上限
   - 限流触发时返回 429 状态码和错误信息
   - 限流计数记录到日志

5. 安全检测模块（security 包）：
   - 异常调用检测器（detector 包）：
     a. HighFrequencyDetector — 高频调用检测
     b. AbnormalTimeDetector — 异常时段调用检测
     c. AuthFailDetector — 连续鉴权失败检测（触发自动 IP 封禁）
     d. AbnormalParamDetector — 异常入参检测（SQL 注入特征、路径穿越、超大 payload）
     e. PermissionBreachDetector — 权限越界检测
   - IP 封禁管理（banner 包）：手动封禁/解封、自动封禁触发、封禁时长管理、针对具体应用封禁
   - 告警通知（alert 包）：站内通知

6. 业务管理接口：
   - 应用管理 CRUD（含 AppKey/AppSecret 生成、状态启停、到期时间设置、IP 白名单管理、限流配置）
   - 接口管理 CRUD（含分组管理、加解密配置）
   - 权限管理（应用-接口授权、批量授权、按分组授权、授权矩阵查询）
   - 调用日志查询（分页、多条件筛选：时间/应用/接口/状态码/IP/是否限流/是否拦截）
   - 安全防护接口（异常事件查询、IP 封禁管理、安全规则配置）
   - 统计仪表盘数据接口（调用量趋势、接口热度、应用排行、错误率、耗时分布 P50/P90/P99）
   - 数据大屏接口（实时调用量、应用访问排行、接口热度、安全态势、调用趋势，支持轮询刷新）

7. 通用功能：
   - 统一返回格式（code/message/data）
   - 全局异常处理（含限流异常、封禁异常、权限异常的专属错误码）
   - 分页封装
   - Knife4j 接口文档配置
   - 操作审计日志 AOP

8. 编写 API 文档到 docs/api.md

确保项目可直接 mvn clean package 编译通过。
```

#### 4A. 安全测评工程师

| 项 | 内容 |
|----|------|

| 产出物 | security/security-report.md |
| 前置依赖 | src/ 目录代码完成 |
| 验收标准 | 安全报告覆盖全部检查项，加解密实现正确，防护机制有效，无高危漏洞 |

**创建任务 Prompt：**

```
你是安全测评工程师。请对 GateKeeper 项目工作空间中的代码进行安全评估。

这是一个 API 权限管理与安全网关系统，安全性至关重要。请重点检查：

1. 网关鉴权链路安全：
   - 12 步处理链路是否有可绕过的环节
   - IP 白名单 CIDR 匹配是否可被绕过（如 X-Forwarded-For 伪造）
   - 应用停用/到期后是否立即生效
   - 权限校验是否每个请求都执行

2. 加解密实现安全：
   - SM2/SM3/SM4 实现是否符合国密标准
   - AES 实现是否使用了安全的模式和密钥长度
   - 密钥是否明文存储在数据库或日志中
   - 密钥传输是否安全
   - 加解密配置的优先级逻辑是否正确（接口级优先于应用级）

3. 限流机制安全：
   - 令牌桶算法是否正确实现
   - Redis 计数是否有竞态条件
   - 限流是否可被绕过

4. IP 封禁机制安全：
   - 封禁是否立即生效
   - 封禁状态是否可被篡改
   - 自动封禁规则是否可被恶意触发（DoS）

5. 异常检测安全：
   - 检测规则是否有效
   - 是否存在误报/漏报风险

6. 常见漏洞：
   - SQL 注入、XSS、CSRF、SSRF（网关转发）
   - 敏感信息泄露（AppSecret、密钥、Token）
   - 输入验证不足

7. 依赖安全：
   - 检查 pom.xml 和 package.json 中依赖版本漏洞
   - Bouncy Castle 版本是否最新

在 security/security-report.md 中编写安全测评报告，包含：
- 检查项清单和检查结果
- 发现的问题（按严重程度分级：高/中/低）
- 修复建议和代码示例
- 加解密实现验证结论
- 安全防护机制有效性验证结论
- 安全等级评定
```
