# 告警中心（Alert Center）功能说明

> 在 GateKeeper 既有「安全事件（security_event）」审计能力之外，新增独立的**运营告警中心**，
> 覆盖网关运行全貌的实时告警，并提供顶栏通知铃铛。

## 1. 设计定位

| 能力 | 安全事件 security_event | 告警 alert（本功能） |
|------|------------------------|----------------------|
| 归属 | 安全审计（安全人员跟进） | 运营告警（运维实时关注） |
| 维度 | 安全规则触发的审计事件 | 网关内部错误 / 限流 / 自动封禁 / 异常入参 |
| 关键属性 | 事件类型、触发规则、处置状态 | **等级（INFO/WARNING/CRITICAL）** + **已读/未读** 状态 |
| 入口 | 安全防护 → 安全事件 | 顶栏铃铛 + 告警中心菜单 |

## 2. 数据模型（alert 表）

- `level`：INFO / WARNING / CRITICAL
- `source`：GATEWAY（网关运行）/ SECURITY（安全检测）/ RATE_LIMIT（限流）/ SYSTEM（系统）
- `status`：0=未读, 1=已读, 2=已处理, 3=已忽略
- 关联字段：`related_app_id` / `related_app_name` / `related_ip`、`handle_remark`、`occurred_at` / `read_at` / `handled_at`

## 3. 后端接口（/alert）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/alert/list` | 分页查询（支持 level / source / status 筛选） |
| GET | `/alert/unread-count` | 未读数量（供铃铛轮询） |
| PUT | `/alert/{id}/read` | 标记单条已读 |
| PUT | `/alert/read-all` | 一键全部已读 |
| PUT | `/alert/{id}/handle` | 处置（status=2 已处理 / 3 已忽略 + 备注） |

核心类：`entity/Alert.java`、`mapper/AlertMapper.java`、`service/AlertService`(+Impl)、`controller/AlertController.java`。

## 4. 告警自动产生点

为降低误报告警噪声，仅在关键链路埋点（均为**追加式**调用，不影响主流程）：

- `GatewayCore` 捕获网关内部异常 → 发布 **CRITICAL / GATEWAY**
- `SecurityDetectionService.autoBanIp` IP 自动封禁 → 发布 **CRITICAL / SECURITY**
- 高频调用（令牌桶）超阈值 → 发布 **WARNING / RATE_LIMIT**
- 异常入参检测 → 发布 **WARNING / SECURITY**
- 权限越界达阈值 → 发布 **WARNING / SECURITY**

> 发布方法 `AlertService.publish(...)` 内部对落库异常做了防御，告警写入失败不影响网关主流程。

## 5. 前端

- `views/alert/Index.vue`：告警中心页（等级/来源/状态筛选、标记已读、处理弹窗、顶部未读/严重统计）
- `components/Layout.vue`：顶栏铃铛改为下拉，显示未读红点计数 + 最近未读告警列表，每 30s 轮询 `/alert/unread-count`
- `api/modules.js`：`getAlertList` / `getAlertUnread` / `markAlertRead` / `markAllAlertRead` / `handleAlert`
- `router/index.js`：新增 `/alert` 路由
