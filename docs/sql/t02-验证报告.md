## 五、踩到的坑

1. **`SMEMBERS` 对不存在的 key 返回空集合（`[]`），而非 null**：
   原版 `readFromCache` 用 `cached != null` 判断没命中，误命中导致 admin 登录始终得到 0 个 perm。
   修复：先用 `redisTemplate.hasKey(key)` 做精确 EXISTS 判断，再读内容。
   单测同步覆盖此分支（`getUserPerms_cacheMiss_fallsBackToDbAndWritesCache` now mocks `hasKey=false`）。

2. **`admin` (user_id=1) 启动时未与 ADMIN 角色绑定**：
   init.sql 只插了 user_role(user_id=1, role_id=1)=SUPER_ADMIN。
   T01 migrate-v2.sql 没补 admin→ADMIN 关联。
   兜底 SQL：`docs/sql/t02-seed-admin-role.sql`（INSERT IGNORE 幂等）。

3. **`grant:approve` 与 `app:credential:revoke` 没有现成接口**：
   原型要求 11 个高危接口都拦截，但 T02 之前只有 7 个对应方法。
   解决方案：T02 新增 `PermissionController.approve`（壳接口，留给 T03 落地审批流），
   以及 `AppController.revokeCredential`（MVP 等价语义：status=0 停用）。

4. **`api:publish` 没有专门的发布生命周期方法**：
   原型 enum 有 `PUBLISH/UNPUBLISHED/DRAFT` 等状态，T02 复用 `InterfaceService.updateStatus(id,1)`
   作为 MVP，T03 上线 `api_publish_status` 全套状态机后替换。
