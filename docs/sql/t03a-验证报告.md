## 四、踩到的坑

| # | 现象 | 根因 / 解决 |
|---|---|---|
| 1 | `DbExec.class` 期望参数为「单条 SQL 字符串」，不接受文件路径 | 自实现 `ApplySeed.java` 解析 `;` + 注释 + 字符串边界切分；用完即删 |
| 2 | Redis <REDIS_HOST>:16379 报 `NOAUTH HELLO must be called with the client already authenticated` | 该 Redis 实例有 auth；为不修改 application.yml（红线），改用 localhost:6379（T02 启动文档里也提到有本地 redis） |
| 3 | 启动 backend 时 maven windows git bash 解析 `${}` 占位符失败 | 用 `export K=V` 包裹变量，把 password 引号包起来避免 shell 解析 `#` |
| 4 | Java 8 不支持 `var` | 把测试里的 `var` 改成 `List<Xxx>` 显式类型 |
| 5 | test lombok 生成的 constructor 包含两个 final 字段（EnvService + CryptoService） | 测试 setUp 改为 `new AppCredentialServiceImpl(envService, cryptoService)` 双参 |
| 6 | `application.yml` 在 working copy 已被人改动（含 GATEKEEPER_* 占位默认值） | 红线"不动 application.yml"——**commit 时只 stage 我自己的文件**，不让 yml 进 commit（pre-commit 钩子也会拦） |
| 7 | brief 的 curl step 5 期望 `uat` 创建返回 200，但任务 spec 强制 `dev/test/pre/prod` | 这是 brief 与 spec 的不一致，遵循 spec（架构 D1 决策）；验证报告里如实记录为"400 符合预期" |
