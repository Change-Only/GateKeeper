## 六、实施的 SQL 兼容补丁（已记录在文件）

1. **MySQL 8 保留字 `sensitive` 加反引号**（schema-v2.sql 第 167、380 行；migrate-v2.sql 第 246、478 行）：MySQL 8.0.17+ 将 `SENSITIVE` 列为保留字，未加反引号会导致 CREATE TABLE 失败。
2. **`gk.schema.version` 显式指定 id=1000**（migrate-v2.sql 第 478 行）：原 SQL 不指定 id 被自动分配为 1，与 `sign.algorithm`（显式 id=1）的 INSERT IGNORE 冲突导致丢种。
3. **biz_line 防御性归位 UPDATE**（migrate-v2.sql §1.2 前置 `UPDATE biz_line SET id=100 WHERE id<>100 AND line_code='common'`）：早期会话变量丢失会让 common 落到 id=6，此 UPDATE 保证从历史错误状态恢复到 id=100。

## 七、过程坑位汇总

1. **DELIMITER 客户端指令**：MySQL JDBC 不识别 `DELIMITER`，采用**策略 A**：自实现 Java 切分器（`docs/sql/_tools/DbExec.java`），按 `DELIMITER <token>` 切换分隔符，自定义模式下整体替换为 `;`（服务器收到合法终止），CREATE PROCEDURE 块正确入库。
2. **存储过程删除顺序**：`DROP PROCEDURE IF EXISTS gk_add_column` 必须放在 `CREATE PROCEDURE` 之前，否则重跑会因已存在而失败；schema-v2.sql 已采用此顺序。
3. **ALTER 守卫**：所有 ALTER 通过 `gk_add_column` / `gk_add_index` 存储过程检查 information_schema 是否已存在，避免重复添加报错。
