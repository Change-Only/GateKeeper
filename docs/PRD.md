## 一、产品概述

### 1.1 产品定位

GateKeeper 是企业级 API 安全网关管理平台，将后端系统接口统一接入、集中管控，对外提供标准化 API 入口。通过应用维度权限管理、IP 白名单、频率限制、国密加解密、异常调用检测与 IP 封禁，实现 API 调用**可管、可控、可防、可审、可视**。

### 1.2 目标用户

| 角色 | 说明 | 核心诉求 |
|------|------|---------|
| 系统管理员 | 负责网关平台运维 | 管理应用、配置权限、监控调用、处理异常 |
| API 调用方（应用开发者） | 需要调用后端接口的应用 | 获取 AppKey、了解接口文档、调试调用 |
| 安全运维人员 | 负责安全审计 | 查看调用日志、安全事件、IP 封禁管理 |
| 管理层 | 关注整体运行情况 | 数据大屏查看运行态势 |

### 1.3 核心价值

- **统一入口**：后端接口经网关统一暴露，无需直连
- **权限可控**：应用维度控制"谁能调用什么接口"
- **加密传输**：国密 SM2/SM3/SM4 + AES
- **流量可限**：QPS/并发/日调用量三维限流，防滥用
- **异常可防**：自动检测异常调用，自动/手动 IP 封禁
- **调用可审**：全链路调用日志，多维度查询
- **态势可视**：数据大屏实时展示运行态势

## 三、用户故事

### 3.1 应用管理

- **US-001**：注册应用并自动生成 AppKey/AppSecret，作为唯一身份凭证。
- **US-002**：为应用设置到期时间，到期后自动失效，避免长期失管风险。
- **US-003**：为应用配置 IP 白名单，仅白名单 IP 可调用，防凭证泄露后被滥用。
- **US-004**：设置调用频率限制（QPS/并发/日调用量），防异常高频调用影响稳定性。
- **US-005**：停用/启用应用，异常时快速阻断其全部调用。

### 3.2 接口管理

- **US-006**：注册后端接口并配置路径、方法、后端服务地址，供网关正确路由。
- **US-007**：接口分组管理，按业务域批量授权。
- **US-008**：为接口配置入参/返参加密策略，保障传输安全。
- **US-009**：配置接口超时时间，各接口可使用不同策略。

### 3.3 权限管理

- **US-010**：为应用授权可调用接口，精确控制访问范围。
- **US-011**：按接口分组批量授权，提高效率。
- **US-012**：通过授权矩阵查看所有应用授权情况，掌握全局权限分布。

### 3.4 加解密管理

- **US-013**：为接口配置 SM4 对称加密，满足国密合规。
- **US-014**：为接口配置 AES 加密，兼容不支持国密的老系统。
- **US-015**：为应用配置 SM2 密钥对，用于签名验证。
- **US-016**：接口级加解密配置优先于应用级，便于特殊接口采用不同策略。

### 3.5 网关代理

- **US-017**：通过统一网关地址携带 AppKey 发起请求，无需关心后端真实地址。
- **US-018**：网关拦截请求时返回明确错误码和原因，便于快速定位。

### 3.6 调用日志

- **US-019**：查看全部 API 调用日志，审计调用行为。
- **US-020**：按时间/应用/接口/状态码/IP 筛选日志，快速定位记录。
- **US-021**：查看每次调用是否被限流或拦截，评估安全策略有效性。

### 3.7 安全防护

- **US-022**：自动检测高频调用并触发告警，及时发现异常。
- **US-023**：连续鉴权失败自动封禁来源 IP，防暴力破解。
- **US-024**：手动封禁指定 IP 并设封禁时长、关联应用，精准处置事件。
- **US-025**：配置安全检测规则的阈值与动作，按业务调整灵敏度。

### 3.8 数据大屏

- **US-026**：通过数据大屏查看实时调用与安全态势，掌握整体运行状态。
- **US-027**：数据大屏自动刷新，展示最新数据。
- **US-028**：调用请求携带签名与防重放参数，防伪造/重放。
- **US-029**：密钥加密存储并支持版本管理与定时轮换，降低泄露风险。
- **US-030**：日志中手机号/身份证等敏感字段自动脱敏，防二次泄露。
- **US-031**：异常告警通过邮件/Webhook/企业微信推送，及时响应。
- **US-032**：后台登录具备 JWT 认证、密码强度校验与失败锁定。
- **US-033**：提供接入 SDK 封装签名与国密加解密，便于快速接入。

## 四、功能详细说明

### 4.1 应用管理

#### 4.1.1 应用注册

- **输入**：应用名称（必填）、描述（选填）、到期时间（选填）
- **处理**：生成 AppKey（32 位随机）与 AppSecret（64 位随机），AppSecret 经 AES 加密后存储；创建应用记录，默认"启用"
- **输出**：创建成功，展示 AppKey/AppSecret（AppSecret 仅展示一次）
- **页面交互**：新增应用 → 填表 → 提交 → 弹窗展示 AppKey/AppSecret，提示"请妥善保存，仅展示一次"

#### 4.1.2 应用编辑

- **可编辑字段**：应用名称、描述、到期时间
- **不可编辑字段**：AppKey、AppSecret、创建时间

#### 4.1.3 应用启停

- 停用：二次确认后状态变为"停用"，该应用所有请求被网关拒绝
- 启用：状态变为"启用"，恢复调用

#### 4.1.4 应用到期时间

- 到期时间精确到日期（yyyy-MM-dd）
- 到期后状态自动变为"已过期"，网关拒绝该应用请求
- 到期前 7 天在大屏和管理后台显示提醒

#### 4.1.5 IP 白名单配置

- 在应用详情页配置；每条规则支持单 IP（192.168.1.1）或 CIDR 网段（192.168.1.0/24），可多条
- 白名单为空时允许所有 IP；不为空时仅白名单内 IP 可访问
- 网关取请求真实 IP（优先 X-Forwarded-For 最后一跳，无则 RemoteAddr）

#### 4.1.6 频率限制配置

| 限制类型 | 说明 | 单位 |
|---------|------|------|
| QPS 限制 | 每秒最大请求数 | 次/秒 |
| 并发限制 | 同时处理中的最大请求数 | 个 |
| 日调用量 | 每日 00:00-23:59 最大请求总数 | 次/日 |

- 三种限制独立配置，任一触发即拒绝
- 触发限流返回 HTTP 429 + 错误信息
- 基于 Redis 令牌桶算法实现
- 各项可设为 0 表示不限制

#### 4.1.7 密钥重置

- 重置 AppSecret 后旧密钥立即失效
- 需二次确认，提示"重置后使用旧 AppSecret 的调用将立即失败"

### 4.2 接口管理

#### 4.2.1 接口注册

- **输入**：接口名称、接口路径（/gateway/ 开头）、请求方法（GET/POST/PUT/DELETE）、所属分组、后端服务地址（完整 URL）、超时时间（ms，默认 5000）、描述
- **处理**：创建接口记录，默认"启用"
- **输出**：接口创建成功

#### 4.2.2 接口加解密配置

- **入参加密配置**：启用开关（是/否）、算法（SM4 / AES / 无）、模式（ECB / CBC / CFB / OFB / CTR）、密钥（Base64）、IV 向量（Base64，ECB 不需要）、填充方式（PKCS5Padding / PKCS7Padding / NoPadding）
- **返参加密配置**：同入参配置
- **优先级**：接口级配置 > 应用级配置 > 无加密

### 4.3 权限管理

#### 4.3.1 授权操作

- 单个授权：选择应用 → 选择接口 → 授权
- 按分组授权：选择应用 → 选择接口分组 → 一键授权该分组下所有接口
- 批量授权：选择应用 → 多选接口 → 批量授权
- 取消授权：单个取消 / 批量取消

#### 4.3.2 授权矩阵

- 行：应用列表；列：接口列表（或接口分组）；单元格：已授权 / 未授权
- 支持在矩阵中直接切换授权状态

### 4.4 加解密管理

#### 4.4.1 支持的算法

| 算法 | 类型 | 用途 | 配置项 |
|------|------|------|--------|
| SM2 | 非对称加密 | 密钥交换、数字签名 | 公钥、私钥、签名模式 |
| SM3 | 密码杂凑 | 数据完整性校验 | 盐值（可选） |
| SM4 | 对称加密 | 数据加密传输 | 密钥、模式（ECB/CBC/CFB/OFB/CTR）、IV、填充方式 |
| AES | 对称加密 | 数据加密传输（国际标准） | 密钥、密钥长度（128/192/256）、模式、IV、填充方式 |
| MD5 | 摘要算法 | 数据摘要（兼容） | 盐值（可选） |
| SHA256 | 摘要算法 | 数据摘要（国际标准） | 盐值（可选） |

#### 4.4.2 配置层级与优先级

```
接口级配置（最高优先级）
    ↓ 未配置时回退
应用级配置
    ↓ 未配置时回退
无加密（明文传输）
```

#### 4.4.3 密钥管理

- 对称密钥（SM4/AES）：Base64 编码存储，数据库中 AES 加密；非对称密钥（SM2）：公钥明文、私钥加密存储
- 密钥托管：加密存储不落明文，运行时解密缓存在内存
- 密钥版本：每次轮换生成新版本并保留历史版本
- 密钥轮换：支持手动/定时，旧密钥保留 30 天过渡期

### 4.5 网关代理核心

#### 4.5.1 请求处理链路（责任链模式）

```
请求到达 /gateway/{path}
    │
    ├─ 1. IP 白名单校验 (IpWhitelistHandler)
    │     不通过 → 返回 403 "IP 不在白名单"
    │
    ├─ 2. IP 封禁检查 (IpBanCheckHandler)
    │     已封禁 → 返回 403 "IP 已被封禁，解封时间：xxx"
    │
    ├─ 3. 应用状态/到期校验 (AppAuthHandler)
    │     AppKey 无效 → 返回 401 "无效的 AppKey"
    │     应用停用 → 返回 403 "应用已停用"
    │     应用过期 → 返回 403 "应用已过期"
    │
    ├─ 4. 频率限制 (RateLimitHandler)
    │     QPS 超限 → 返回 429 "请求频率超限"
    │     并发超限 → 返回 429 "并发数超限"
    │     日量超限 → 返回 429 "日调用量超限"
    │
    ├─ 5. 接口权限校验 (PermissionHandler)
    │     无权限 → 返回 403 "无权调用此接口"
    │     接口不存在 → 返回 404 "接口不存在"
    │
    ├─ 6. 入参解密 (EncryptionHandler)
    │     解密失败 → 返回 400 "入参解密失败"
    │
    ├─ 7. 请求转发 (ForwardHandler)
    │     后端超时 → 返回 504 "后端服务超时"
    │     后端异常 → 返回 502 "后端服务异常"
    │
    ├─ 8. 响应加密 (EncryptionHandler)
    │
    ├─ 9. 日志记录 (LogHandler, 异步)
    │
    └─ 10. 返回响应给调用方
```

#### 4.5.2 请求认证方式

调用方通过 HTTP Header 传递认证信息：

```
X-App-Key: {AppKey}
X-Timestamp: {毫秒时间戳}
X-Nonce: {随机字符串}
X-Signature: {签名}
```

签名算法：`SM3(AppKey + AppSecret + Timestamp + Nonce)`

### 4.6 调用日志

#### 4.6.1 日志记录字段

| 字段 | 说明 |
|------|------|
| log_id | 日志唯一 ID |
| app_id | 调用方应用 ID |
| app_name | 应用名称（冗余，便于查询） |
| interface_id | 接口 ID |
| interface_path | 接口路径 |
| request_method | 请求方法 |
| request_time | 请求时间 |
| request_params | 入参（JSON，加密接口记录密文） |
| response_data | 响应数据（JSON，加密接口记录密文） |
| response_status | 状态码 |
| cost_time | 耗时（ms） |

| encryption_algorithm | 加密算法（无/SM4/AES） |
| is_rate_limited | 是否被限流 |
| is_blocked | 是否被拦截 |
| block_reason | 拦截原因 |

#### 4.6.2 日志查询

- 筛选条件：时间范围、应用、接口、状态码、IP、是否限流、是否拦截
- 支持分页、日志详情查看（完整入参/响应）、导出 CSV

#### 4.6.3 敏感数据脱敏

- 日志落库前对入参/响应敏感字段自动脱敏
- 脱敏字段：手机号、身份证号、银行卡号、Token、密码、AppSecret 等
- 方式：保留首尾，中间以 `***` 替换
- 支持配置脱敏字段清单与规则

#### 4.6.4 日志归档与分区

- 调用日志表按月归档/清理（MySQL 不物理分区，超期迁移历史表或直接清理）
- 超期日志（默认 90 天）自动归档清理，策略可在系统配置中调整

### 4.7 安全防护

#### 4.7.1 异常调用检测规则

| 规则 | 检测条件 | 触发动作 | 默认阈值 |
|------|---------|---------|---------|
| 高频调用 | 单应用 QPS > 阈值持续 N 秒 | 限流 + 告警事件 | QPS > 100 持续 30 秒 |
| 异常时段调用 | 非配置时间段内有调用 | 告警事件 | 23:00-06:00 |
| 连续鉴权失败 | 同一 IP+AppKey N 分钟内失败超过 M 次 | 自动封禁 IP（可配时长） | 5 分钟内失败 10 次，封禁 1 小时 |
| 异常入参 | 入参含 SQL 注入特征/路径穿越/超 1MB | 拦截 + 告警事件 | - |
| 权限越界 | 应用 N 分钟内尝试未授权接口超过 M 次 | 告警 + 可选自动封禁 | 10 分钟内超过 20 次 |

#### 4.7.2 IP 封禁管理

- **手动封禁**：管理员指定 IP + 关联应用（可选，空则全局封禁）+ 封禁时长 + 原因
- **自动封禁**：安全检测规则触发，按规则配置的时长自动封禁
- **生效/解封**：实时写入 Redis（TTL = 封禁时长）并同步数据库；手动解封或到期自动解封（详见 §8.3、§8.4）
- **封禁列表**：查看当前封禁 IP、关联应用、剩余封禁时间、封禁原因

#### 4.7.3 安全事件

- 每次异常检测触发都生成安全事件记录，记录事件类型、描述、关联应用、关联 IP、触发规则、处理状态（待处理/已处理/已忽略）、发生时间
- 支持按事件类型、状态、时间范围筛选

#### 4.7.4 告警通知多渠道

- 告警渠道：站内通知、邮件、Webhook、企业微信；每类安全事件可独立配置渠道
- 支持告警级别（提示/警告/严重）与分级推送，可配置接收人

## 五、网关请求处理链路详细说明

### 5.1 完整处理流程

```
[调用方] → HTTP 请求 → [GateKeeper Gateway]

  Header: X-App-Key, X-Timestamp, X-Nonce, X-Signature
  Body: 加密后的请求参数（如果接口配置了入参加密）

Step 1: IpWhitelistHandler
  - 获取客户端真实 IP
  - 查询应用的 IP 白名单
  - 白名单为空 → 放行
  - 白名单不为空 → 校验 IP 是否在白名单（CIDR 匹配）
  - 不在白名单 → 中断，返回 403

Step 2: IpBanCheckHandler
  - 查询 Redis: ip_ban:{ip}:{appId} (全局封禁查 ip_ban:{ip}:global)
  - 存在封禁记录 → 中断，返回 403 + 解封时间
  - 封禁已过期 → 清除 Redis 记录，放行

Step 3: AppAuthHandler
  - 根据 X-App-Key 查询应用
  - 应用不存在 → 中断，返回 401
  - 应用状态 = 停用 → 中断，返回 403
  - expire_time < 当前时间 → 中断，返回 403
  - 校验签名: SM3(AppKey + AppSecret + Timestamp + Nonce) == X-Signature
  - 签名不匹配 → 中断，返回 401 + 记录鉴权失败（触发安全检测）
  - Timestamp 超过 5 分钟 → 中断，返回 401 "请求已过期"

Step 4: RateLimitHandler
  - 从 Redis 令牌桶获取令牌
  - QPS 令牌桶为空 → 中断，返回 429
  - 并发计数 +1，检查并发限制 → 超限则中断，返回 429
  - 日调用计数 +1，检查日调用量 → 超限则中断，返回 429
  - 记录限流日志

Step 5: PermissionHandler
  - 根据请求路径匹配 api_interface
  - 接口不存在 → 中断，返回 404
  - 查询 app_api_permission(app_id, interface_id)
  - 无授权记录 → 中断，返回 403 + 记录权限越界（触发安全检测）

Step 6: EncryptionHandler (入参解密)
  - 查询接口加解密配置（接口级优先，回退应用级）
  - 无加密配置 → 放行明文参数
  - 有加密配置 → 使用配置的算法和密钥解密请求 Body
  - 解密失败 → 中断，返回 400

Step 7: ForwardHandler
  - 构造后端请求（URL、Method、Headers、Body）
  - 使用 RestTemplate 发起请求（超时 = 接口配置的超时时间）
  - 后端超时 → 中断，返回 504
  - 后端异常 → 中断，返回 502
  - 获取后端响应

Step 8: EncryptionHandler (响应加密)
  - 有响应加密配置 → 使用配置的算法和密钥加密响应 Body
  - 无加密配置 → 直接返回明文

Step 9: LogHandler (异步)
  - 异步线程记录完整调用日志到 api_call_log
  - 包含：应用、接口、时间、入参（密文）、响应（密文）、耗时、状态码、IP、加密算法、是否限流、是否拦截

Step 10: 返回响应
  - 将处理后的响应返回给调用方
```

## 六、加解密策略说明

### 6.1 各算法适用场景

| 算法 | 适用场景 | 说明 |
|------|---------|------|
| SM2 | 签名验证、密钥交换 | 调用方用私钥签名，网关用公钥验签 |
| SM3 | 签名摘要、完整性校验 | 生成请求摘要，防篡改 |
| SM4 | 请求参数加密、响应数据加密 | 国密合规场景的首选对称加密 |
| AES | 请求参数加密、响应数据加密 | 兼容不支持国密的老系统 |
| MD5 | 简单摘要（不推荐） | 仅兼容场景使用 |
| SHA256 | 安全摘要 | 国际标准摘要 |

### 6.2 加解密流程

**请求方向（入参解密）**：调用方按配置算法/密钥加密请求参数 → 密文入 Body → 网关 EncryptionHandler 同法解密 → 明文转发后端服务。

**响应方向（返参加密）**：后端服务返回明文 → 网关 EncryptionHandler 同法加密 → 密文返回调用方 → 调用方同法解密。

### 6.3 密钥安全方案

- 对称密钥（SM4/AES）AES-256 加密存储、运行时解密缓存内存；非对称私钥（SM2）加密存储、运行时解密使用
- 密钥不打印日志、不在 API 响应中返回

## 七、异常检测规则说明

### 7.1 高频调用检测

- 检测条件、默认阈值（QPS > 100 持续 30 秒）、触发动作见 §4.7.1 表；**配置项**：QPS 阈值、持续时间、是否启用

### 7.2 异常时段调用检测

- 检测条件、默认时段（23:00-06:00）、触发动作见 §4.7.1 表；**配置项**：异常时段起止时间、是否启用

### 7.3 连续鉴权失败检测

- 检测条件、默认阈值（5 分钟内失败 10 次，封禁 1 小时）、触发动作见 §4.7.1 表；**配置项**：时间窗口、失败次数、封禁时长、是否启用

### 7.4 异常入参检测

- 可疑模式：SQL 注入特征（' OR '1'='1, UNION SELECT 等）、路径穿越特征（../, ..\, /etc/passwd 等）、超大 payload（超过 1MB）；拦截动作见 §4.7.1 表；**配置项**：payload 大小上限、是否启用

### 7.5 权限越界检测

- 检测条件、默认阈值（10 分钟内超过 20 次）、触发动作见 §4.7.1 表；**配置项**：时间窗口、尝试次数、是否自动封禁、封禁时长

## 八、IP 封禁机制说明

### 8.1 封禁类型

| 类型 | 触发方式 | 说明 |
|------|---------|------|
| 手动封禁 | 管理员操作 | 指定 IP + 可选关联应用 + 封禁时长 + 原因 |
| 自动封禁 | 安全规则触发 | 按规则配置的时长自动封禁 |

### 8.2 封禁范围

- **全局封禁**：封禁 IP 对所有应用的调用（关联应用为空）；**应用级封禁**：仅封禁对特定应用的调用（关联应用不为空）

### 8.3 封禁生效机制

1. 写入 Redis：`ip_ban:{ip}:{appId 或 global}`，TTL = 封禁剩余秒数
2. 同步写入数据库 ip_ban 表
3. 网关 IpBanCheckHandler 查询 Redis（O(1)），实时生效

### 8.4 解封机制

- **手动解封**：管理员在封禁列表点击"解封"；**自动解封**：Redis TTL 到期自动清除，数据库状态更新为"已解封"
