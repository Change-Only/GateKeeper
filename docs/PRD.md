## 一、产品概述

### 1.1 产品定位

GateKeeper 是一个企业级 API 安全网关管理平台，将企业内各后端系统的接口统一接入、集中管控，对外提供标准化的 API 调用入口。通过应用维度的权限管理、IP 白名单、频率限制、国密加解密、异常调用检测与 IP 封禁，实现 API 调用的**可管、可控、可防、可审、可视**。

### 1.2 目标用户

| 角色 | 说明 | 核心诉求 |
|------|------|---------|
| 系统管理员 | 负责网关平台运维 | 管理应用、配置权限、监控调用、处理异常 |
| API 调用方（应用开发者） | 需要调用后端接口的应用 | 获取 AppKey、了解接口文档、调试调用 |
| 安全运维人员 | 负责安全审计 | 查看调用日志、安全事件、IP 封禁管理 |
| 管理层 | 关注整体运行情况 | 数据大屏查看运行态势 |

### 1.3 核心价值

- **统一入口**：所有后端接口通过网关统一暴露，调用方无需直连后端服务
- **权限可控**：应用维度精确控制"谁能调用什么接口"
- **加密传输**：国密 SM2/SM3/SM4 + AES，保障数据传输安全
- **流量可限**：QPS/并发/日调用量三维限流，防止滥用
- **异常可防**：自动检测异常调用，自动/手动 IP 封禁
- **调用可审**：全链路调用日志，支持多维度查询
- **态势可视**：数据大屏实时展示运行态势

## 三、用户故事

### 3.1 应用管理

- **US-001**：作为系统管理员，我希望能够注册新的调用方应用并自动生成 AppKey/AppSecret，以便为应用分配唯一身份凭证。
- **US-002**：作为系统管理员，我希望能够为应用设置到期时间，以便应用到期后自动失效，避免长期未管理的应用带来安全风险。
- **US-003**：作为系统管理员，我希望能够为应用配置 IP 白名单，以便限制只有指定 IP 才能发起调用，防止凭证泄露后被非法利用。
- **US-004**：作为系统管理员，我希望能够为应用设置调用频率限制（QPS/并发/日调用量），以便防止应用异常高频调用影响系统稳定性。
- **US-005**：作为系统管理员，我希望能够停用/启用应用，以便在发现异常时快速阻断该应用的全部调用。

### 3.2 接口管理

- **US-006**：作为系统管理员，我希望能够注册后端接口并配置其路径、方法和后端服务地址，以便网关能够正确路由请求。
- **US-007**：作为系统管理员，我希望能够将接口分组管理，以便按业务域批量授权。
- **US-008**：作为系统管理员，我希望能够为接口配置入参/返参加密策略，以便保障传输数据安全。
- **US-009**：作为系统管理员，我希望能够配置接口超时时间，以便不同接口可以有不同的超时策略。

### 3.3 权限管理

- **US-010**：作为系统管理员，我希望能够为应用授权可调用的接口，以便精确控制每个应用的访问范围。
- **US-011**：作为系统管理员，我希望能够按接口分组批量授权，以便提高授权效率。
- **US-012**：作为系统管理员，我希望能够通过授权矩阵查看所有应用的授权情况，以便快速了解全局权限分布。

### 3.4 加解密管理

- **US-013**：作为系统管理员，我希望能够为接口配置 SM4 对称加密，以便满足国密合规要求。
- **US-014**：作为系统管理员，我希望能够为接口配置 AES 加密，以便兼容不支持国密的老系统。
- **US-015**：作为系统管理员，我希望能够为应用配置 SM2 密钥对，以便进行数字签名验证。
- **US-016**：作为系统管理员，我希望接口级加解密配置优先于应用级配置，以便特殊接口可以使用不同的加密策略。

### 3.5 网关代理

- **US-017**：作为应用开发者，我希望通过统一的网关地址携带 AppKey 发起请求，以便无需关心后端服务的真实地址。
- **US-018**：作为系统管理员，我希望网关在请求被拦截时返回明确的错误码和原因，以便调用方能够快速定位问题。

### 3.6 调用日志

- **US-019**：作为安全运维人员，我希望能够查看所有 API 调用的完整日志，以便审计调用行为。
- **US-020**：作为安全运维人员，我希望能够按时间、应用、接口、状态码、IP 等条件筛选日志，以便快速定位特定调用记录。
- **US-021**：作为安全运维人员，我希望能够看到每次调用是否被限流或拦截，以便评估安全策略的有效性。

### 3.7 安全防护

- **US-022**：作为安全运维人员，我希望系统能自动检测高频调用并触发告警，以便及时发现异常行为。
- **US-023**：作为安全运维人员，我希望系统能在连续鉴权失败时自动封禁来源 IP，以便防止暴力破解。
- **US-024**：作为安全运维人员，我希望能够手动封禁指定 IP 并设置封禁时长和关联应用，以便精准处置安全事件。
- **US-025**：作为安全运维人员，我希望能够配置安全检测规则的阈值和动作，以便根据实际业务调整检测灵敏度。

### 3.8 数据大屏

- **US-026**：作为管理层，我希望通过数据大屏查看实时调用情况和安全态势，以便了解系统整体运行状态。
- **US-027**：作为系统管理员，我希望数据大屏能够自动刷新，以便看到最新数据。
- **US-028**：作为应用开发者，我希望调用请求需要携带签名和防重放参数，以便防止请求被伪造或重放。
- **US-029**：作为系统管理员，我希望密钥加密存储并支持版本管理和定时轮换，以便降低密钥泄露风险。
- **US-030**：作为安全运维人员，我希望调用日志中的手机号、身份证等敏感字段自动脱敏，以便防止二次泄露。
- **US-031**：作为系统管理员，我希望异常告警能通过邮件、Webhook、企业微信等渠道推送，以便及时响应。
- **US-032**：作为系统管理员，我希望后台登录具备 JWT 认证、密码强度校验和失败锁定，以便保障管理后台安全。
- **US-033**：作为应用开发者，我希望有现成的接入 SDK 封装签名和国密加解密，以便快速接入网关。

## 四、功能详细说明

### 4.1 应用管理

#### 4.1.1 应用注册

- **输入**：应用名称（必填）、描述（选填）、到期时间（选填）
- **处理**：
  - 生成唯一 AppKey（32 位随机字符串）
  - 生成 AppSecret（64 位随机字符串）
  - AppSecret 使用 AES 加密后存储
  - 创建应用记录，状态默认为"启用"
- **输出**：应用创建成功，展示 AppKey 和 AppSecret（AppSecret 仅展示一次）
- **页面交互**：点击"新增应用"→ 填写表单 → 提交 → 弹窗展示 AppKey/AppSecret → 提示"请妥善保存 AppSecret，仅展示一次"

#### 4.1.2 应用编辑

- **可编辑字段**：应用名称、描述、到期时间
- **不可编辑字段**：AppKey、AppSecret、创建时间

#### 4.1.3 应用启停

- 点击"停用"→ 二次确认 → 应用状态变为"停用"→ 该应用所有请求被网关拒绝
- 点击"启用"→ 应用状态变为"启用"→ 恢复调用

#### 4.1.4 应用到期时间

- 到期时间精确到日期（yyyy-MM-dd）
- 到期后应用状态自动变为"已过期"→ 网关拒绝该应用请求
- 到期前 7 天在大屏和管理后台显示到期提醒

#### 4.1.5 IP 白名单配置

- 在应用详情页配置 IP 白名单
- 每条规则支持单 IP（192.168.1.1）或 CIDR 网段（192.168.1.0/24）
- 支持添加多条规则
- 白名单为空时，允许所有 IP 访问（不限制）
- 白名单不为空时，仅白名单内 IP 可访问
- 网关校验时获取请求真实 IP（优先取 X-Forwarded-For 最后一跳，无则取 RemoteAddr）

#### 4.1.6 频率限制配置

| 限制类型 | 说明 | 单位 |
|---------|------|------|
| QPS 限制 | 每秒最大请求数 | 次/秒 |
| 并发限制 | 同时处理中的最大请求数 | 个 |
| 日调用量 | 每日 00:00-23:59 最大请求总数 | 次/日 |

- 三种限制独立配置，任一触发即拒绝
- 触发限流时返回 HTTP 429 + 错误信息
- 限流基于 Redis 令牌桶算法实现
- 各项可设为 0 表示不限制

#### 4.1.7 密钥重置

- 重置 AppSecret 后旧密钥立即失效
- 需二次确认，提示"重置后使用旧 AppSecret 的调用将立即失败"

### 4.2 接口管理

#### 4.2.1 接口注册

- **输入**：接口名称、接口路径（/gateway/ 开头）、请求方法（GET/POST/PUT/DELETE）、所属分组、后端服务地址（含完整 URL）、超时时间（ms，默认 5000）、描述
- **处理**：创建接口记录，状态默认"启用"
- **输出**：接口创建成功

#### 4.2.2 接口加解密配置

- **入参加密配置**：
  - 是否启用入参加密（是/否）
  - 加密算法（SM4 / AES / 无）
  - 加密模式（ECB / CBC / CFB / OFB / CTR）
  - 密钥（Base64 编码）
  - IV 向量（Base64 编码，ECB 模式时不需要）
  - 填充方式（PKCS5Padding / PKCS7Padding / NoPadding）
- **返参加密配置**：同入参配置
- **优先级**：接口级配置 > 应用级配置 > 无加密

### 4.3 权限管理

#### 4.3.1 授权操作

- 单个授权：选择应用 → 选择接口 → 授权
- 按分组授权：选择应用 → 选择接口分组 → 一键授权该分组下所有接口
- 批量授权：选择应用 → 多选接口 → 批量授权
- 取消授权：单个取消 / 批量取消

#### 4.3.2 授权矩阵

- 行：应用列表
- 列：接口列表（或接口分组）
- 单元格：已授权 / 未授权
- 支持在矩阵中直接切换授权状态

### 4.4 加解密管理

#### 4.4.1 支持的算法

| 算法 | 类型 | 用途 | 配置项 |
|------|------|------|--------|
| SM2 | 非对称加密 | 密钥交换、数字签名 | 公钥、私钥、签名模式 |
| SM3 | 密码杂凑 | 数据完整性校验 | 盐值（可选） |
| SM4 | 对称加密 | 数据加密传输 | 密钥、模式（ECB/CBC/CFB/OFB/CTR）、IV、填充方式 |
| AES | 对称加密 | 数据加密传输（国际标准） | 密钥、密钥长度（128/192/256）、模式、IV、填充方式 |
| MD5 | 摘要算法 | 数据摘要（兼容） | 盐值（可选） |
| SHA256 | 摘要算法 | 数据摘要（国际标准） | 盐值（可选） |

#### 4.4.2 配置层级与优先级

```
接口级配置（最高优先级）
    ↓ 未配置时回退
应用级配置
    ↓ 未配置时回退
无加密（明文传输）
```

#### 4.4.3 密钥管理

- 对称密钥（SM4/AES）：Base64 编码存储，数据库中 AES 加密
- 非对称密钥（SM2）：公钥明文存储，私钥加密存储
- 密钥托管：密钥加密存储，不落明文，运行时解密缓存在内存
- 密钥版本管理：每次轮换生成新版本，保留历史版本
- 密钥轮换：支持手动/定时轮换，旧密钥保留 30 天过渡期

### 4.5 网关代理核心

#### 4.5.1 请求处理链路（责任链模式）

```
请求到达 /gateway/{path}
    │
    ├─ 1. IP 白名单校验 (IpWhitelistHandler)
    │     不通过 → 返回 403 "IP 不在白名单"
    │
    ├─ 2. IP 封禁检查 (IpBanCheckHandler)
    │     已封禁 → 返回 403 "IP 已被封禁，解封时间：xxx"
    │
    ├─ 3. 应用状态/到期校验 (AppAuthHandler)
    │     AppKey 无效 → 返回 401 "无效的 AppKey"
    │     应用停用 → 返回 403 "应用已停用"
    │     应用过期 → 返回 403 "应用已过期"
    │
    ├─ 4. 频率限制 (RateLimitHandler)
    │     QPS 超限 → 返回 429 "请求频率超限"
    │     并发超限 → 返回 429 "并发数超限"
    │     日量超限 → 返回 429 "日调用量超限"
    │
    ├─ 5. 接口权限校验 (PermissionHandler)
    │     无权限 → 返回 403 "无权调用此接口"
    │     接口不存在 → 返回 404 "接口不存在"
    │
    ├─ 6. 入参解密 (EncryptionHandler)
    │     解密失败 → 返回 400 "入参解密失败"
    │
    ├─ 7. 请求转发 (ForwardHandler)
    │     后端超时 → 返回 504 "后端服务超时"
    │     后端异常 → 返回 502 "后端服务异常"
    │
    ├─ 8. 响应加密 (EncryptionHandler)
    │
    ├─ 9. 日志记录 (LogHandler, 异步)
    │
    └─ 10. 返回响应给调用方
```

#### 4.5.2 请求认证方式

调用方通过 HTTP Header 传递认证信息：

```
X-App-Key: {AppKey}
X-Timestamp: {毫秒时间戳}
X-Nonce: {随机字符串}
X-Signature: {签名}
```

签名算法：`SM3(AppKey + AppSecret + Timestamp + Nonce)`

## 五、网关请求处理链路详细说明

### 5.1 完整处理流程

```
[调用方] → HTTP 请求 → [GateKeeper Gateway]

  Header: X-App-Key, X-Timestamp, X-Nonce, X-Signature
  Body: 加密后的请求参数（如果接口配置了入参加密）

Step 1: IpWhitelistHandler
  - 获取客户端真实 IP
  - 查询应用的 IP 白名单
  - 白名单为空 → 放行
  - 白名单不为空 → 校验 IP 是否在白名单（CIDR 匹配）
  - 不在白名单 → 中断，返回 403

Step 2: IpBanCheckHandler
  - 查询 Redis: ip_ban:{ip}:{appId} (全局封禁查 ip_ban:{ip}:global)
  - 存在封禁记录 → 中断，返回 403 + 解封时间
  - 封禁已过期 → 清除 Redis 记录，放行

Step 3: AppAuthHandler
  - 根据 X-App-Key 查询应用
  - 应用不存在 → 中断，返回 401
  - 应用状态 = 停用 → 中断，返回 403
  - expire_time < 当前时间 → 中断，返回 403
  - 校验签名: SM3(AppKey + AppSecret + Timestamp + Nonce) == X-Signature
  - 签名不匹配 → 中断，返回 401 + 记录鉴权失败（触发安全检测）
  - Timestamp 超过 5 分钟 → 中断，返回 401 "请求已过期"

Step 4: RateLimitHandler
  - 从 Redis 令牌桶获取令牌
  - QPS 令牌桶为空 → 中断，返回 429
  - 并发计数 +1，检查并发限制 → 超限则中断，返回 429
  - 日调用计数 +1，检查日调用量 → 超限则中断，返回 429
  - 记录限流日志

Step 5: PermissionHandler
  - 根据请求路径匹配 api_interface
  - 接口不存在 → 中断，返回 404
  - 查询 app_api_permission(app_id, interface_id)
  - 无授权记录 → 中断，返回 403 + 记录权限越界（触发安全检测）

Step 6: EncryptionHandler (入参解密)
  - 查询接口加解密配置（接口级优先，回退应用级）
  - 无加密配置 → 放行明文参数
  - 有加密配置 → 使用配置的算法和密钥解密请求 Body
  - 解密失败 → 中断，返回 400

Step 7: ForwardHandler
  - 构造后端请求（URL、Method、Headers、Body）
  - 使用 RestTemplate 发起请求（超时 = 接口配置的超时时间）
  - 后端超时 → 中断，返回 504
  - 后端异常 → 中断，返回 502
  - 获取后端响应

Step 8: EncryptionHandler (响应加密)
  - 有响应加密配置 → 使用配置的算法和密钥加密响应 Body
  - 无加密配置 → 直接返回明文

Step 9: LogHandler (异步)
  - 异步线程记录完整调用日志到 api_call_log
  - 包含：应用、接口、时间、入参（密文）、响应（密文）、耗时、状态码、IP、加密算法、是否限流、是否拦截

Step 10: 返回响应
  - 将处理后的响应返回给调用方
```

## 六、加解密策略说明

### 6.1 各算法适用场景

| 算法 | 适用场景 | 说明 |
|------|---------|------|
| SM2 | 签名验证、密钥交换 | 调用方用私钥签名，网关用公钥验签 |
| SM3 | 签名摘要、完整性校验 | 生成请求摘要，防篡改 |
| SM4 | 请求参数加密、响应数据加密 | 国密合规场景的首选对称加密 |
| AES | 请求参数加密、响应数据加密 | 兼容不支持国密的老系统 |
| MD5 | 简单摘要（不推荐） | 仅兼容场景使用 |
| SHA256 | 安全摘要 | 国际标准摘要 |

### 6.2 加解密流程

**请求方向（入参解密）：**
1. 调用方使用配置的算法和密钥加密请求参数
2. 将密文放入请求 Body
3. 网关 EncryptionHandler 使用相同算法和密钥解密
4. 将明文参数转发给后端服务

**响应方向（返参加密）：**
1. 后端服务返回明文响应
2. 网关 EncryptionHandler 使用配置的算法和密钥加密响应
3. 将密文返回给调用方
4. 调用方使用相同算法和密钥解密获取明文

### 6.3 密钥安全方案

- 对称密钥（SM4/AES）：数据库中 AES-256 加密存储，运行时解缓存在内存中
- 非对称私钥（SM2）：数据库中加密存储，运行时解密使用
- 密钥不在日志中打印
- 密钥不在 API 响应中返回

## 七、异常检测规则说明

### 7.1 高频调用检测

- **检测条件**：单应用 QPS 持续超过阈值
- **默认阈值**：QPS > 100，持续 30 秒
- **触发动作**：自动触发限流 + 生成告警安全事件
- **配置项**：QPS 阈值、持续时间、是否启用

### 7.2 异常时段调用检测

- **检测条件**：在配置的非工作时间有调用
- **默认配置**：异常时段 23:00-06:00
- **触发动作**：生成告警安全事件
- **配置项**：异常时段起止时间、是否启用

### 7.3 连续鉴权失败检测

- **检测条件**：同一 IP + AppKey 在 N 分钟内鉴权失败超过 M 次
- **默认阈值**：5 分钟内失败 10 次
- **触发动作**：自动封禁该 IP（针对该应用），默认封禁 1 小时
- **配置项**：时间窗口、失败次数、封禁时长、是否启用

### 7.4 异常入参检测

- **检测条件**：入参中包含可疑模式
  - SQL 注入特征（' OR '1'='1, UNION SELECT 等）
  - 路径穿越特征（../, ..\, /etc/passwd 等）
  - 超大 payload（超过 1MB）
- **触发动作**：拦截请求 + 生成告警安全事件
- **配置项**：payload 大小上限、是否启用

### 7.5 权限越界检测

- **检测条件**：应用在 N 分钟内尝试调用未授权接口超过 M 次
- **默认阈值**：10 分钟内超过 20 次
- **触发动作**：生成告警安全事件 + 可选自动封禁
- **配置项**：时间窗口、尝试次数、是否自动封禁、封禁时长

## 八、IP 封禁机制说明

### 8.1 封禁类型

| 类型 | 触发方式 | 说明 |
|------|---------|------|
| 手动封禁 | 管理员操作 | 指定 IP + 可选关联应用 + 封禁时长 + 原因 |
| 自动封禁 | 安全规则触发 | 按规则配置的时长自动封禁 |

### 8.2 封禁范围

- **全局封禁**：封禁 IP 对所有应用的调用（关联应用为空）
- **应用级封禁**：封禁 IP 对特定应用的调用（关联应用不为空）

### 8.3 封禁生效机制

1. 写入 Redis：`ip_ban:{ip}:{appId 或 global}`，TTL = 封禁剩余秒数
2. 同步写入数据库 ip_ban 表
3. 网关 IpBanCheckHandler 查询 Redis（O(1)），实时生效

### 8.4 解封机制

- **手动解封**：管理员在封禁列表点击"解封"
- **自动解封**：Redis TTL 到期自动清除，数据库状态更新为"已解封"

| 自动刷新 | 数据按配置间隔自动刷新 |

### 11.8 补充功能验收

| 验收项 | 验收条件 |
|--------|---------|
| 请求签名 | 无签名或签名错误返回 401；Timestamp 超时返回 401；重复 Nonce 被拒绝 |
| 密钥托管 | 数据库中无明文密钥；密钥轮换后旧密钥失效、新密钥生效 |
| 日志脱敏 | 日志中的手机号/身份证/Token 等字段已脱敏展示 |
| 告警多渠道 | 异常事件触发后按配置推送至邮件/Webhook/企业微信 |
| 登录安全 | JWT 认证生效；连续登录失败达阈值后账号锁定 |
| SDK 接入 | 使用 SDK 可完成签名 + 加解密调用，与网关互通 |
