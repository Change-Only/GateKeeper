## 2. `t09-hygiene.sql` 真实内容逐条（修正版，替代原 §4.1）

> ⚠️ 原 §4.1 把本文件误描成「靠 `LIKE '%重复%'` + 裸 `OR` 宽删」——**与真实文件不符**（本表用 `pid` 不是 `parent_id`，且无 `OR`）。以下为 `docs/sql/t09-hygiene.sql` 实文（逐条贴）。

```sql
-- 1) 删除 sys_menu 野行 221（带四重守卫：任一不满足即不删）
DELETE FROM sys_menu
WHERE id = 221
  AND pid = 5
  AND type = 2
  AND route_path = '/sys/bizline'
  AND name = '业务线管理'
  AND NOT EXISTS (SELECT 1 FROM sys_role_menu WHERE menu_id = 221)
  AND NOT EXISTS (SELECT 1 FROM (SELECT id FROM sys_menu WHERE pid = 221) AS _children);

-- 2) alert.alarm_level → 仅改列注释（不改表结构）
ALTER TABLE alert MODIFY COLUMN alarm_level TINYINT NULL DEFAULT NULL
  COMMENT '【T09 起废弃·死列】…';

-- 3) app.audit_status → 仅改列注释（不改表结构）
ALTER TABLE app MODIFY COLUMN audit_status TINYINT NOT NULL DEFAULT 1
  COMMENT '【T09 核实：预留列】…';

-- 4) 字典 alarm_level 的 remark 澄清作用域
UPDATE sys_dict
SET remark = '仅映射 alarm_rule.alarm_level…', updated_at = NOW()
WHERE dict_code = 'alarm_level';
```

**逐条判据**：
- **语句 1（DELETE）**：**空卷首跑【会删 1 行】，不是 no-op。** 野行 `sys_menu.id=221` 由**本初始化链自己在 `04-t03a-seed-permissions.sql:33` 创建**（`(221, 5, '业务线管理', 2, NULL, '/sys/bizline', 0, 3, 1)`）；全仓无任何 `sys_role_menu` 引用 221 ⇒ 两个 `NOT EXISTS` 守卫全部通过 ⇒ 命中 1 行。**它就是这套 hygiene 存在的全部意义。** 已运行库重跑：221 已不存在 ⇒ 命中 0 行 ⇒ 幂等。
  > 计数更正：源文件 `t09-hygiene.sql:16` 自注「带四重守卫」**措辞不精确**——实际 `WHERE` 共 **7 个条件** = **5 列等值锁定**（`id`/`pid`/`type`/`route_path`/`name`）**+ 2 处 `NOT EXISTS`**。本 doc 上文 SQL 块保留源文件原文（verbatim），此处以本注更正计数。
- **语句 2/3（ALTER MODIFY）**：team-lead 直连 DB 比对 definition —— `alert.alarm_level` 实际 `tinyint NULL DEFAULT NULL`、`app.audit_status` 实际 `tinyint NOT NULL DEFAULT 1`，均与原定义**恒等**，仅替换 COMMENT ⇒ **不改表结构、反复执行恒等**。（`app.audit_status` 本就是 NOT NULL，故「MODIFY NOT NULL 遇 NULL 抛 1138」风险不存在。）
- **语句 4（UPDATE WHERE）**：带 `WHERE dict_code='alarm_level'`，反复执行结果恒等 ⇒ 幂等。
- **旁证**：dev 库现状 `sys_menu` 总数 **112**（= 脚本自注 113−1）、`id=221` 计数 **0** ⇒ 语句 1 真实生效过。

## 6. E2E 脚本 ↔ 真实 API 静态交叉核对（T10-E / #46）

> **动机**：本机无 Docker，`docs/sql/t09-docker-e2e.sh` 是整条 Docker 链路**唯一的运行时验证手段且一次都没跑过**；若脚本的端点路径或 JSON 取值路径写错，将来跑起来会**给出错误的绿灯**（比不跑更危险）。故在具备 Docker 前，先把它与真实代码逐条对一遍。
> **方法**：端点用**全仓** `grep -r`（不按目录扫——同类控制器**平铺**在 `controller/`、`alarm/`、`block/`、`grant/` 等子包，按目录扫是历史假阴性来源）；JSON 取值逐条核**被调方法的真实返回类型**（`Result<T>` 信封固定 `{code,message,data}`，字段是 **`message` 不是 `msg`**；`data` 在**裸数组**与 `PageResult{records,total}` 之间混用）。
> **基座事实**（实测）：`application.yml:5` `context-path=/api`（对外全部带 `/api` 前缀，类级 `@RequestMapping` 不再重复）；`src/frontend/nginx.conf:15-16` `location /api/ → proxy_pass http://backend:8080`（**保留** `/api` 前缀转发）；`common/Result.java:38-44` `success()` 置 **`code=200`**。
