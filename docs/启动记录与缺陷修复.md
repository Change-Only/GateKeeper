## 三、本次发现并修复的缺陷

### 1. 🔴 管理接口零鉴权（P0 安全）

- **现象**：不带令牌访问 `/api/dashboard/screen/overview` 返回 200，全部管理接口裸奔。
- **根因**：应用已配置 `server.servlet.context-path=/api`，而 `WebConfig` 中拦截器写的是 `.addPathPatterns("/api/**")`。Spring MVC 的拦截器匹配基于**去掉 context-path 之后**的路径（即 `/dashboard/...`），原规则永远命中不了。
- **修复**：拦截规则改为 `/**`，白名单同步改为 `/auth/login`（gateway、doc.html、swagger 资源、`/error` 保持放行）。
- **验证**：无令牌访问 → 401；带令牌访问 → 200。

### 2. 🔴 前端登录 404（P0 阻断）

- **现象**：点击登录报 404，管理后台完全进不去。
- **根因**：`AuthController` 类级注解为 `@RequestMapping("/api/auth")`，与 context-path `/api` 叠加后实际路径变成 `/api/api/auth/login`，而前端请求的是 `/api/auth/login`。
- **修复**：类级路径改为 `/auth`；`WebConfig` 白名单与 Javadoc 同步修正。
- **验证**：经 8081 代理 `POST /api/auth/login` 返回 200 + token。

### 3. 🟡 真实数据库密码被安全黑名单拦截（启动阻断）

- **现象**：启动自检报“数据库密码为历史默认值，禁止启动（设置新的 GATEKEEPER_DB_PASSWORD）”。
- **处理**：**新建/复用专用应用账号 `gatekeeper`（未改动 root 密码，避免影响 DBeaver 等既有工具）**，设强口令并授予 `gatekeeper.*` 库级权限，应用改用该账号连接。
- **遗留**：`Yzxyzx@1234` 仍存在于 git 历史中，正式环境应轮换 root 口令并从历史中清理。

### 4. 🟡 环境注入 `SERVER__PORT=0` 导致端口随机

- **现象**：后端启动后 Tomcat 落到随机端口（如 63063）。
- **根因**：当前 shell 环境存在 `SERVER__PORT=0`，被 Spring Boot 宽松绑定解析为 `server.port=0`。
- **处理**：启动时显式传 `--server.port=8080`（命令行参数优先级高于环境变量）。

### 5. 🟡 `target/gatekeeper.jar` 被外部进程锁死

- **现象**：`mvn package` 在 repackage 阶段失败：`Unable to rename gatekeeper.jar to gatekeeper.jar.original`，产物被截成 222KB 的薄 jar（`java -jar` 会失败）。
- **处理**：用临时 POM（finalName 改为 gatekeeper-dev）打出可用 fat jar，再**就地覆盖**回 `gatekeeper.jar`（该锁允许写入、不允许删除/重命名）。现已恢复为 58MB 可用 fat jar，`java -jar` 与 Docker 构建正常。
- **提示**：若再次遇到，用同样的“新文件名构建 + 就地覆盖”方式绕过，或先释放占用进程（杀毒/索引器）。
