# 原型枚举字典（APIM 重新设计 · 实施硬前提）

> **作用**：原型 MOCK 数据里大量字段是裸数字或裸字符串，语义藏在页面组件的渲染代码（标签数组 / 颜色映射 / 索引数组）中。这份字典是工程师写实体类、SQL 注释、前端渲染、迁移脚本的唯一权威来源。
>
> **来源**：从 `docs/prototype/api-platform-原型.html` 提取（MOCK 数据在 `<script>` 块 [3]，页面组件在块 [4]–[7]，MENU_TREE 在块 [8]；扫描标签数组 `['A','B','C'][idx]`、`statusTag: function(s){...}` 颜色映射、三元 `=== N ? 'X' : 'Y'`）。
>
> **标签约定**：✅ = 直接从原型标签数组确认；🟡 = 推断（原型未明写但有合理依据）；📌 = 现有 GateKeeper 既有语义（PRD 中已明确）。

## 二、告警等级（alarmLevel，1/2/3 三档）

> 与现有 `alert.level` 完全一致（INFO / WARNING / CRITICAL）。

| 取值 | 标签 | 颜色 | 适用场景（来自原型 alarmRecords MOCK） |

| 1 | INFO | info | 僵尸接口告警、风险提示 |

## 十、网关拦截阶段（rejectStage，callLogs，**关键**）

> 原型出现的样本：`'ACL'`, `'RATELIMIT'`, `'SIGNATURE'`, `'APPKEY'`, `'NONCE'`, `'UPSTREAM'`，共 6 个。
> PM 提到 8 阶段 P0 待补。**架构师已确认 5 子阶段**（AppAuthHandler 内部拆 时间戳/Nonce/AppKey/状态/签名）。完整 8 阶段推断：

| 取值 | 标签 | 所在处理器 | 说明 |
|---|---|---|---|
| `IP_WHITELIST` | IP 白名单 | IpWhitelistHandler | 客户端 IP 不在白名单 |
| `APPKEY` | AppKey 校验 | AppAuthHandler（子阶段） | AppKey 不存在或已停用 |
| `NONCE` | Nonce 校验 | AppAuthHandler（子阶段） | 5 分钟内重复请求 |
| `TIMESTAMP` | 时间戳校验 | AppAuthHandler（子阶段） | 时间戳超出容忍窗 |
| `SIGNATURE` | 签名校验 | AppAuthHandler（子阶段） | 签名不匹配 |
| `ACL` | 权限校验 | PermissionHandler | 应用未授权该接口 |
| `RATELIMIT` | 限流 | RateLimitHandler | QPS/日/并发超限 |
| `PARAM` | 参数校验 | AbnormalParamCheckHandler | 黑名单参数/超长/类型错 |
| `UPSTREAM` | 后端失败 | LogHandler 之后的转发 | 后端 5xx 或超时 |

> **注**：原始网关责任链可能还有 `BLOCK`（命中 IP/应用封禁）阶段，待架构师最终确认是合并到 ACL 还是独立列出。

## 十七、字典（dicts）

原型 6 个字典（来自 MOCK.dicts.dictCode）：
- `app_type` — 应用类型（值见 §五）
- `visibility` — 接口可见性（值见 §七）
- `api_status` — 接口状态（值见 §一 apis）
- `grant_status` — 授权状态（值见 §一 grants）
- `cred_status` — 凭证状态（值见 §一 credentials）
- `alarm_level` — 告警等级（值见 §二）

> **机制**：这些是 `sys_dict` + `sys_dict_item` 的种子数据。前端下拉和后端校验都从字典读，**不在代码里硬编码**。schema-v2.sql 的种子数据中已包含这 6 个字典 22 个 item。
